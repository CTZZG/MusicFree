# 存储可靠性与备份恢复（2026-10-28）

用户已确认优先处理数据丢失边界、备份完整性和分享组合emoji；个人备份继续保留插件自定义配置，隐私加密不作为本轮要求。版本仍0.13.1/400036、Android14/API34；本分支基于PR61，不包含合并或发布操作。Mesh与长曲续听继续暂缓。

## 存储决定

- 缺文件与读失败分开。临时I/O错误、无法恢复的残缺快照和未来格式不会变成可写空表；失败promise不缓存为完成态。
- 未载入成功时，待写操作留在内存，flush走原有有界重试并返回false；先完成读取才能迁移旧MMKV。动态准备、启动准备都可重试，迁移期间的删除标记跨失败保留。
- 快照提交采用同目录`.tmp`→主文件，旧主文件先移至`.bak`；不会先删除唯一有效主文件，也不会在失败后删除候选和恢复副本。主文件缺失可读`.bak`；主文件残缺时由真实codec确认上一快照，损坏原件最多保留一份`.corrupt`。首次写入只有完整`.tmp`时也可恢复；只有残片时阻止初始化。
- 未来版本主文件不会回滚成旧格式。恢复副本仍需通过当前格式完整校验，失败时保留原文件。`.bak`是上一完整快照，恢复可能回退最近修改；这不等于绝对零丢失或物理掉电/fsync保证。
- 初始化读取失败使用现有对话框给出重新读取入口；不继续初始化空歌单。日志只记录store ID和错误类别，不导出快照内容。
- 平台后端仍为RNFS，没有新增原生模块或存储依赖。正常写入多一次旧快照重命名，原批量延迟策略保持。显式remove会清理主文件及恢复文件，避免删掉的store被恢复副本重新载入。

## 备份格式与取舍

新JSON顶层`version:3`，保留旧的musicSheets/localMusicSheet/starredMusicSheets/plugins/pluginBackupV2字段；无顶层version的原备份继续可导入，未知版本在修改数据前拒绝。

歌单恢复返回逐项结果和原ID→新ID映射。新歌单保留封面/作者/描述/创建时间与排序偏好；同名合并优先保留本地自定义元数据。分组、置顶只映射已恢复的歌单，不将旧ID直接写回，也不覆盖已有分组。所有恢复模式沿用原有追加/合并我喜欢/合并同名语义。

`preferences`只包含首页顺序和显隐、首页模式、资料库列表/网格、分组/置顶。没有扩为整个App.config恢复，不恢复自动播放意图、存储路径、权限或网络策略。旧备份没有preferences时不覆盖本机布局。备份仍包含插件配置，按用户自用场景保留。

本地音频和封面仍是路径引用，不包含二进制文件；换机须另行迁移文件。设置页和恢复预览说明这一边界。恢复完成前等待键值存储flush，逐项失败或落盘失败会显示未完成提示和结果报告。

远程URL恢复沿用受限HTTP客户端。已解析的JSON对象直接交给原预览解析器，避免再次String转换成`[object Object]`。实际Axios变换加真实设置页测试覆盖对象/文本/网络失败/无效JSON，旧处理器同测1败3过；此为本轮补验前确认的原有恢复入口故障。

## 分享文本

只调整静态卡片换行和省略。优先用Intl.Segmenter；Hermes缺少该API时保留常见ZWJ emoji、肤色修饰符、旗帜、组合重音和变体选择符。fallback是有明确覆盖范围的兼容实现，不宣称完整Unicode所有复杂文字分词。保持保守字宽预算，不改变歌词切字时间轴、时钟或动效策略，无新增依赖。
