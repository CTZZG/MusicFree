# Android 14 支持决定与接手记录（2026-10-18）

## 首先执行的产品决定

用户明确选择最低 Android 14 / API 34，以减少兼容分支和维护成本。
**不要继续 Android 7/8 验收，也不要未经新的产品决定恢复 Android 7–13 支持。**
安装与播放采用相同下限；targetSdk 仍 36，版本仍 0.11.6 / 400032。
本 PR 尚未发布；既有 v0.11.6 标签、APK 和历史发布说明不变。

维护者（包括 Claude）交接时先读 `docs/architecture.md` 的支持决定，再读此记录。
本轮没有合并、发布或修改其他人的分支。

## 实现边界

- minSdk 设为 34，正常合并 libmpv AAR（依赖声明 API26 低于应用下限）。删除 overrideLibrary，
  不为支持声明重建任何 libmpv/FFmpeg/JNI 二进制。
- 删除 Android7 输入焦点补丁、ISRG Root X1 附加证书及测试、独立 API24 链接器检查、
  只服务旧 DEX 名称限制的解析器和测试。正常系统证书/TLS 校验、库来源/字节一致性和 NewApi lint 保留。
- 通知渠道、不可变 PendingIntent、动态 receiver 导出标记、覆盖窗口、窗口尺寸和 MediaStore 写入授权
  只保留支持范围内的现代路径。READ_EXTERNAL_STORAGE 从最终清单移除；仍需 READ_MEDIA_AUDIO 和通知运行时授权，
  SAF URI 自带授权、用户权限拒绝处理均保留。
- 删除应用与两个既有补丁中的低版本降级；保留真正需要的无模糊目标降级、非 Android 分支和 Android16 Live Update 判断。
  开屏页的正常绘制/延后移除机制、250ms / 0.25s 连续性门限和所有暂停观察窗不变。
- 删除一直遍历空服务列表的 Nitro 退出/反射诊断遗留；对外 playbackServices 仍为空数组，mpv 的状态诊断不变。
- 删除旧镜像 API24/26、x86 选项和移动数据/额外证书链调试配置，Beta 固定 Android14 x86_64；
  Android16 仍使用独立原生/真实 JS 检查。焦点替身也最低 API34。
- 仅旧系统会用到的传统桌面图标资源已删除；保留正在使用的自适应图标前景、背景和 XML。

## 性能与验收规则

减小兼容代码、资源和自定义检查量是维护成本的改进，不自动证明冷启动或播放更快。
用同一 Android14 配置跑现有 perf 套件（预热一次＋十次记录、中位数/P95），分别记录源码、APK 来源与脚本提交。
不为得到好数字删除首个有效读数、跳过失败前提或扩大窗口。`all` 不含 library/perf，不能把三者混写。

本地先用 SDK36 编译 app/test APK、Debug 单测和 NewApi lint，再在自己的 Android14 软件虚拟机检查。
软件虚拟机不是 ARM 真机或物理音频验证。最终 Android14 全量功能与独立 library/perf、Android16 原始样本均需真实核对。
当前正在验证，最终数字追加到 PR #46 描述；不把旧头结果填作新 API34 代码的结果。

Android14 新候选的 Beta177 `all` 已独立核对109项通过。复用同一APK的 Beta178 `library`
只完成安装（1 PASS / 1 FAIL），首页等待超时，截图是系统桌面、crash buffer为空；
扫描尚未执行，不能算音乐库通过。原脚本丢弃了 `am start -W` 输出，早期日志又被后续日志覆盖，
所以尚不足以确认启动失败原因或称为环境偶发故障。现保留启动命令输出、退出码、首次logcat及Activity/Window状态，
明确命令错误立即失败；首页和播放观察窗口不变。后续仅用同一Beta177 APK复验此套件，不重复打包。
