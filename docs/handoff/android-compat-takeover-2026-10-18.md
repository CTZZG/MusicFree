# Android 14 支持决定与接手记录（2026-10-18）

## 首先执行的产品决定

用户明确选择最低 Android 14 / API 34，以减少兼容分支和维护成本。
**不要继续 Android 7/8 验收，也不要未经新的产品决定恢复 Android 7–13 支持。**
安装与播放采用相同下限；targetSdk 仍 36，版本仍 0.11.6 / 400032。
本 PR 尚未发布；既有 v0.11.6 标签、APK 和历史发布说明不变。

维护者（包括 Claude）交接时先读 `docs/architecture.md` 的支持决定，再读此记录。
本轮没有合并、发布或修改其他人的分支。

## 实现边界

- minSdk 设为 34，正常合并 libmpv AAR（依赖声明 API26 低于应用下限）。删除 overrideLibrary，
  不为支持声明重建任何 libmpv/FFmpeg/JNI 二进制。
- 删除 Android7 输入焦点补丁、ISRG Root X1 附加证书及测试、独立 API24 链接器检查、
  自定义 DEX 名称解析器和测试。Android14 允许方法名含空格，但逗号、括号和单引号仍不合法；
  测试保持驼峰命名，真实 D8 构建仍是必需检查，不把删除解析器解释为允许任意反引号方法名。
  正常系统证书/TLS 校验、库来源/字节一致性和 NewApi lint 保留。
- 通知渠道、不可变 PendingIntent、动态 receiver 导出标记、覆盖窗口、窗口尺寸和 MediaStore 写入授权
  只保留支持范围内的现代路径。READ_EXTERNAL_STORAGE 从最终清单移除；仍需 READ_MEDIA_AUDIO 和通知运行时授权，
  SAF URI 自带授权、用户权限拒绝处理均保留。
- 删除应用与两个既有补丁中的低版本降级；保留真正需要的无模糊目标降级、非 Android 分支和 Android16 Live Update 判断。
  开屏页的正常绘制/延后移除机制、250ms / 0.25s 连续性门限和所有暂停观察窗不变。
- 删除一直遍历空服务列表的 Nitro 退出/反射诊断遗留；对外 playbackServices 仍为空数组，mpv 的状态诊断不变。
- 删除旧镜像 API24/26、x86 选项和移动数据/额外证书链调试配置，Beta 固定 Android14 x86_64；
  Android16 仍使用独立原生/真实 JS 检查。焦点替身也最低 API34。
- 仅旧系统会用到的传统桌面图标资源已删除；保留正在使用的自适应图标前景、背景和 XML。

## 性能与验收规则

减小兼容代码、资源和自定义检查量是维护成本的改进，不自动证明冷启动或播放更快。
用同一 Android14 配置跑现有 perf 套件（预热一次＋十次记录、中位数/P95），分别记录源码、APK 来源与脚本提交。
不为得到好数字删除首个有效读数、跳过失败前提或扩大窗口。`all` 不含 library/perf，不能把三者混写。

本地先用 SDK36 编译 app/test APK、Debug 单测和 NewApi lint，再在自己的 Android14 软件虚拟机检查。
软件虚拟机不是 ARM 真机或物理音频验证。最终 Android14 全量功能与独立 library/perf、Android16 原始样本均需真实核对。
产品代码为332c12ca；后续b2ff9b96补启动取证，6d6f008a补同机对照，不改变运行逻辑。
截至6d6f008a，CI166实际质量门1397 Jest / 40 generator / 1257 layout、ESLint 0错误/216警告，
新增对照自测6项通过；实际Debug JVM和NewApi lint通过，XML27套147项失败/错误/跳过0。
Android16 #86合法APK缓存命中，编译skipped，87/87原生/辅助/仪器项code0；native25、slow73、
JS70、UI20及两PNG、冻结5齐全并独立检查，冻结确为RAW_STALLED，七个暂停窗口无进度变化。
正常转场差−0.049000058s、最大轮询间隔103ms，未改250ms/.25s门限。
这些是该头的实际结果；后续只清理导入、空行和固定Wi-Fi变量，不将旧云端执行冒称为新头运行。

### 性能实测不能写成已提速

Beta176（旧614 APK）与 Beta179（新332 APK）各4阶段、每阶段预热1+记录10，原始44行均已独立重算。
新一轮主页首帧中位数/P95是2437/3580ms，旧轮1744.5/2056ms；在线点播到引擎进度860→837ms，
本地点播366→395.5ms。清理兼容分支没有证明提速，冷启动观测反而慢了约40%。
两轮虚拟机规格相同、宿主不同；启动进程、原生首帧和渲染阶段都变慢，但这还不足以断言原因是宿主或产品代码。
`perf-cold-compare.sh` 在同一宿主、同一模拟器上按旧/新/旧交叉测量，每组重新安装、准备相同插件，
复用既有冷启动指标与预热1+有效10次；缺任一组或有效样本就失败，不从较快的重跑中挑结果。
仅复用已经构建的APK，不新增产品实现或重打大包。

Beta181（run39121549174，脚本6d6）已完成同机对照；旧614 APK来自Beta172，新332来自Beta177，
build按设计skipped。三组各11行（预热1+有效10），共33行原始数据和51唯一PASS/0FAIL均独立重算。
主页首帧实际提交时间，单位ms：

| 组别 | 中位数 | P95 |
|---|---:|---:|
| 旧包前测 | 3026.5 | 4948 |
| 新包 | 2807.5 | 2894 |
| 同一旧包后测 | 2782 | 2934 |

新包比后测旧包高0.92%，旧包自身前后下降8.08%。本次未复现可归因于清理的约40%退化，也未证实提速；
单次顺序区块不能证明宿主是此前差异的唯一原因。跨机器慢约40%的观测继续保留，不挑更快重跑来写提速。

自有API34软件虚拟机已实际安装本地app/test APK并拉回字节核对。JUnit日志11项完成、10通过1失败：
`lateServiceReceivesPlayingMetadataAndProgressWithoutAnotherStateEvent` 读取时会话9.407s、引擎10.8789s，
超出原1秒容差；外层等候300秒超时，随后仪器断开UiAutomation也报错。原失败保存，未改容差或称本地全通过。
此2CPU、无KVM软件环境与云端硬件加速Android14/16结果分别记录，不冒充真机或物理音频验证。

### Android16 #87 的真实失败与取样修正

2c85fd67 的 CI167 已实际通过；Debug单测与NewApi lint真实执行，独立XML27套147项失败/错误/跳过0。
API87（run39123978054）cache miss并实际编译app/test APK，87项仪器用例全部code0，原生25条和
AudioTrack一方法6轮/288样本齐全，但之后的独立慢加载校验失败，因此整个设备工作流失败。
真实JS70/UI20/冻结5均未执行，不能用前一轮结果顶替。

失败样本来自临时焦点打断后的loaded-playing：引擎已恢复，位置2.415357771s超过目标2.144160199s，
loadingGeneration=-1，通知动作“暂停”，但媒体会话此刻为BUFFERING(6)，不满足严格的PLAYING(3)。
用例先等到会话PLAYING，再单独等引擎前进，最后重新读取并留证；断言与导出记录不是同一次快照，
所以JUnit可能成功，而留存的记录被独立校验拒绝。不能只凭87项code0把这次运行写成通过。

修订限于测试：保留原12秒等待和50ms轮询，取得同时满足引擎前进/非暂停、装载完成、会话PLAYING、
通知“暂停”的快照后，直接保存这份已验证快照；不在判断后另读一次。暂停后的1.2秒观察窗保持，
直接断言将被留存的暂停记录。所有加载期13条观察与完整状态事件仍保留，没有改播放器逻辑。
独立Python校验规则不变，本次原始坏记录仍会失败；自检补三种错误会话状态，21项通过。
测试专用AwaitedSnapshot的两个本地JVM用例通过，改成判断后重新取样的对照在两项中失败一项；
持续BUFFERING即使位置前进也必须在原截止时间失败。该测试类显式加入设备清单，不能只编译而不执行。
本地SDK36实际重新编译app、AndroidTest Kotlin并执行完整Debug JVM：28套149项失败/错误/跳过0。
没有改主应用源码、版本、原生库或独立校验规则，不重打Beta；修复后的完整设备工作流仍需新头实际验收。
这是测试取证一致性修正，不据此断言实际设备的所有短暂缓存事件都已证明无害。

  不改播放、焦点、通知、开屏时序、系统下限或观察窗口。

  补丁从锁定且校验完整性的全新npm源码无偏移应用，结果与安装文件一致。
