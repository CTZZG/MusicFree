# 只读当前播放信息

本轮承接用户“按建议顺序实施”：分享可靠性、性能基线、只读播放信息，最后根据实际录屏决定播放页/迷你条的必要优化。PR57/58 仍待人工复核，不合并、不发布；版本保持 0.13.1/400036、API34。长曲逐曲续听与 Mesh 继续暂缓。

## 功能与边界

- 当前歌曲菜单新增“当前播放信息”。沿用当前歌曲、音质及实际备用来源，分别显示歌曲原来源、实际播放来源、插件音质标签，以及当前文件的编码、采样率、声道数、估计码率。未知字段明确显示“未知”，例如插件标注 128k 的真实 16kbps 测试文件，不能显示成 128kbps。
- 新增原生 getter 在现有 owner/main 线程读取 `audio-codec-name`、`audio-params/samplerate`、`audio-params/channel-count`、`audio-bitrate`。它不读取 `audio-out-params`，不表示声卡/DAC 或物理出声。码率可能是估计值，未补充容器、位深、独占或无损判定。
- 未初始化、未加载、加载中、停止、实际路径不匹配时返回空快照，不初始化播放器。原生返回媒体身份/加载代次和四个白名单字段，不导出 URL、headers 或任意原始对象。每个参数独立处理缺失、异常、非有限/越界值；编码文本限安全的短名称。
- adapter 在读取前后校验媒体和加载代次，包括同一首歌换音质、切走后切回；原生再核对实际路径。面板只在打开、现有切歌/状态事件和手动刷新时读取，2 秒查询期限后回到未知并允许重试。关闭时退订，已关闭或过期结果不回写，没有轮询、第二套进度/播放状态或后台常驻查询。
- 不触发播放、暂停、claim、seek、焦点、hold、元数据推送或新的 JS 播放事件；不修改 libmpv、依赖、播放取源超时、250ms/.25s、首个新读数或暂停窗。分享/歌词/Home 既有行为保留。
- 面板可滚动、支持三语、1–2 倍字体及横屏，保留 48dp 刷新目标，长标题换行。只对当前歌曲显示菜单项，不为未播放歌曲伪造参数。

## 本地验证与负对照

- adapter 和真实面板合计 53 项 Jest：未加载不读、只读无命令、原生身份不符、同歌换音质迟到结果、切歌迟到结果、关闭退订、查询期限、未知/敏感文本及真实 16kbps 与 128k 标签分离。删除 adapter 代次/身份保护时，同样测试有 3 项失败；恢复后全部通过。
- SDK36、真实 React 0.85.3/MPV AAR、实际产品 `MpvPlayerModule`/新 helper 和新仪器 Kotlin 已做定向编译，未改的相邻类由先前项目真实 classes.jar 提供。首次定向编译 classpath 缺 AndroidX Media，补齐实际依赖后通过。这不是一次新的完整 Gradle App 构建，也不是本地设备运行。
- 原生参数 reader 真实 Kotlin/JUnit 4 项通过。相同测试字节码分别加载取消编码保护、取消数值有效性保护的实现，各有 1 项失败；产品源码未装入 mutant。
- 新面板另有 72 组真实组件 Yoga 布局（小屏/横屏、三语、1–2 倍字体、未知/已解码）。初次缺 `mediaUtils` 存储边界 stub，补齐媒体身份替身后通过；没有降低布局断言。
- 新设备仪器通过真实模块/JNI 加载 22.05kHz 单声道与 48kHz 双声道 WAV，记录未初始化、暂停多次只读、切换前/切换中/切换后五份快照。该仪器单独使用 `ao=null` 隔离硬件输出，不替代原有默认后端时钟/慢加载/JS/冻结验收。独立检查器要求五份原始证据完整、代次匹配及暂停不动。
- Beta 全量脚本在真实分享接收后、C 已主动暂停期间打开播放信息，核对 MP3/16kHz/单声道/16kbps 及实际来源，刷新并截图，再恢复原分享/歌词工具流程。底部字段滚动到可见后断言，不改变任何引擎观察窗口。

最终本地完整质量门已通过：201 套 / 1473 项 Jest、40 项 generator、1437 项布局，ESLint 0 错误 / 215 警告、TypeScript、静态检查、循环依赖及 7 个补丁重放均通过。首次完整检查被新文件的 Prettier 默认单引号/花括号规则与项目 ESLint 冲突拦住，按项目 ESLint 纠正后完整重跑通过；基线未放宽。新工作区没有 Release manifest，相关静态分支按设计跳过，不能称本轮 Release manifest 已审计。

本次云端实际结果记录在 PR 描述与外部 progress.json。新的 getter 需要本次新 App/test APK、CI/API36 及一次候选 Release Beta；旧 Beta214 的 APK 不覆盖新产品。尚未执行的设备步骤不得写为通过。无需为文档结果频繁移动 head 取消设备工作流。

## 性能基线与后续顺序

此前同一分享候选 Beta214 的 E2E-only #215 四类测量各预热 1 次、有效 10 次；home-drawn median/P95 为 2301.5/4129ms，固定测试源搜索 13/30ms，在线引擎推进 646/936ms，本地 286/449ms。不是公共源公网搜索延迟，也不是声卡出声时间。

独立旧→新→旧 #216 同机对照各预热 1 次、有效 10 次；中位数/P95 为 2985/4766、2732/2911、2808.5/3019ms。旧包自身存在波动，不能宣称分享补丁稳定提速。两次性能工作流的主机不同，不交叉比较。额外诊断帧显示系统移除 starting view 以后仍有开屏画面，真实 home-drawn 约 2847ms；不通过改打点、删慢样本来“提速”。

只读信息验收后再检查实际播放页/迷你条录屏、慢封面、快速切歌、返回、旋转和减少动态设置。有明确跳变/浪费才做最小修补，复用现有导航、封面代次及播放意图，不能为增加动效而另造播放器状态。真机 ARM、耗电、实体车机、物理音频、商业分享接收方和新整包独立证书没有本轮新证明。

## Beta217 的入口错误与实际录屏补验

Beta217 的新安装包真实构建成功；Release / Debug XML 均为 36 套 180 项、失败/错误/跳过 0。API118 的 93 个原生方法、五份新参数快照及原有时钟/慢加载/JS/UI/冻结证据已独立验收。Beta217 的 all 只到 21 PASS / 1 FAIL：分享返回并关闭面板后已在完整播放页，旧脚本却点击仅属于迷你条的“歌曲: …”节点，因此尚未打开信息面板就失败。不能把它写成参数 getter 或播放故障，也不能宣称后续下载/Doze/迁移等已经在新包完成。

依据真实失败截图和界面树，入口改为播放页“更多操作”→“当前播放信息”，关闭后直接使用播放页顶部分享按钮。保留最小记录树作入口回归，真实旧 flow 在同树被拒，新 flow 通过。产品代码、Android、依赖和版本未改；补验复用 Beta217 APK，仅更换 E2E 脚本，不再重打包。

用户随后要求继续按录屏评估播放页与迷你条。补验同时保留原 A→B→C 选歌流程的录屏，并在 C 已暂停期间录制正常设置、横屏、系统移除动画三组进入/返回。只调用已有 UI，保存前后实际 MediaSession，原暂停检查不变；系统旋转/三个动画标量在正常完成及错误返回时恢复。视频须真实拉回并完整解码，横屏必须有实际横屏 PNG，不能用“设置请求成功”或静态截图充当完整录屏。视频使用半分辨率减轻采集负担，同时保留实际全尺寸 PNG；不拿录制耗时或帧率当作无采集时的性能。编排/录制边界有失败传播与恢复测试，特别要求错误保留在主 harness 的失败计数中，但这些宿主替身不是设备验收。

是否顺滑、是否有跳变要在新视频完成后逐帧评估，当前未添加产品动效。A/B/C 沿用同一张测试封面，选歌录屏只能评估标题/状态与界面衔接，不能证明不同歌曲的迟到封面正确性；慢封面与高频跳歌仍需独立受控证据，不冒充已覆盖。云端准确脚本 head、复用包来源、run 与结果留在 PR 描述及外部 progress.json。
