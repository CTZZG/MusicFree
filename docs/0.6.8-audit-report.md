# MusicFree 0.6.8 产品、性能与稳定性审计归档

审计日期：2026-07-12  
审计基线：`feat/mpv-player` / `cae57799`  
目标版本：`0.6.8`（本轮不升版本）

## 1. 审计结论

本轮从首页与快捷入口、歌单管理、本地音乐、下载、智能歌单、音源管理、播放条、安全边界和发布流程九条用户旅程审计。原始基线存在歌单数据丢失窗口、外部链接静默执行插件、正式包允许无签名发布、文件状态扫描 I/O 峰值、重复背景合成和依赖漏洞等发布阻断项。

本轮已关闭已确认的 P0，并完成高价值 P1 强壮化；0.6.8 可作为新的发布候选。尚未处理的架构级风险列在“剩余风险”，不得在发行说明中宣称插件已完全沙箱化或已完成 Android 新权限体系迁移。

## 2. 已完成修复

### 数据安全与交互

- 歌单编辑数据增加所属标签身份，切换期间清空并锁定旧列表，阻止收藏歌单误写入本地歌单。
- 标签切换和离开页面统一提供“保存 / 不保存 / 取消”。
- 保存改为 `async/await`，写入成功才清除脏状态；失败保留编辑现场。
- 歌单索引先持久化，再提交内存并清理孤立歌曲数据，消除半提交丢失窗口。
- 删除歌曲时同步更新 `worksNum`，并保留用户自定义封面。
- 文件选择器增加 generation，迟到的旧目录读取不能覆盖当前目录。
- 播放列表补充元数据变化时可刷新，修复过期初始滚动下标。

### 性能与内存

- 本地文件状态解析统一为共享缓存：最大并发 6、同路径请求去重、成功/失败分级 TTL、4000 条 LRU。
- 本地音乐页面取消无界 `Promise.all(exists)`；列表行复用页面结果并拒绝迟到状态。
- 下载进度每 500ms 更新不再触发全部历史文件扫描，只在完成任务 key/path 签名变化时增量检查。
- 本地封面缓存增加 300 条 LRU、失败短 TTL 和路径级失效。
- MediaCache 淘汰改为每批 25 条的可等待异步清理，避免同步删除 750 条和未跟踪 Promise 风暴。
- 智能歌单拆分静态曲库索引与动态评分，按输入引用/revision 缓存；最近添加兼容多种时间字段。
- 智能歌单歌手、专辑、来源不再永久截断，默认显示摘要并可展开全部。
- 首页第三方榜单请求增加 10 秒超时，失败不阻塞其他首页模块。
- 音源诊断日志由父列表一次解析，避免每张卡片重复读取并解析 MMKV。

### 界面、动效与无障碍

- 每个路由只保留一个全屏背景所有者；AppBar 不再重新绘制全屏渐变/模糊，消除断层与重复 overdraw。
- 透明 AppBar 在浅色主题使用正文色，修复白底白字。
- 快捷页面安全区覆盖左右边缘，改善横屏刘海和圆角设备。
- 音源管理子页面统一使用透明宽松 AppBar。
- 空闲空列表显示明确空态，不再出现纯空白页。
- 全局动效遵循系统“减少动画”，AppBar 菜单动画由 500ms 收敛到 200ms。
- 播放条点击改为手势成功结束后进入详情；滑动切歌增加并发锁和失败兜底。
- 图片错误状态与 source 绑定，FlashList 复用时不会继承上一项失败占位。

### 安全与发布

- 外部 Deep Link 安装插件/LX 音源必须展示来源、完整 HTTPS 地址和第三方代码风险，并由用户确认。
- 拒绝 HTTP、内嵌账号密码、localhost、环回、链路本地、常见私网及 IPv4-mapped IPv6 地址。
- 备份恢复中的网络插件地址复用相同 URL 安全策略。
- 移除 `global.mmkv` 全局存储暴露。
- MPV MediaBrowser 仅向 UID/包名一致且被 AndroidX 判定为可信媒体控制方的客户端开放。
- 正式 Tag/手动 Release 缺少签名或验签失败时立即终止；Beta 未签名产物明确标记 `UNSIGNED-TEST-ONLY`。
- 正式 APK 使用 `apksigner` 验签并固定证书 SHA-256：`d6ff76f4b8d7b43d3e58bca3fa3f9607d364ab13217c35bf63e05df4efbaa1fd`。
- Release Action 新增 TypeScript/静态审计、全量 Jest、patch-package、Critical 依赖审计和 diff 检查。
- 升级 Axios、WebDAV、Application Insights 依赖链；生产依赖 Critical 从 1 降为 0，High 从 7 降为 4。
- Nitro 审计脚本适配 `react-native-nitro-player@1.4.3`，补齐新 seam 文件和 App 级 FFmpeg AAR 接入检查。

## 4. 性能基线与解释

本轮重点降低页面 I/O 峰值、重复 MMKV 解析、重复模糊合成和同步大批量淘汰。真机空闲内存仍较高：TOTAL PSS 约 477MB、TOTAL RSS 约 621MB。代码确认 MPV 后端会在启动阶段初始化原生服务和恢复播放源；延迟初始化可能影响恢复播放、通知和自动播放语义，未在 0.6.8 中做高风险重构。

后续应使用 Perfetto/React Profiler 和 1 万首本地歌曲、1000 条下载、50 个音源的数据集量化，而不能仅凭空库首屏判断大型曲库性能。

## 5. 剩余风险与后续版本建议

以下不阻断本轮强壮化归档，但仍需明确记录：

1. 插件仍通过 JS `Function` 在应用进程内执行，尚不是真正能力沙箱；URL 校验也不能完全防御 DNS rebinding 和服务端 HTTPS 重定向到私网。
2. WebDAV 密码、插件变量和部分下载 headers 仍未迁移到 Android Keystore；普通备份仍缺少用户密码加密和完整性签名。
3. 备份恢复的本地绝对路径仍需进一步建立允许目录与“可删除原文件”信任标记。
4. `targetSdkVersion=30`、所有文件访问和明文网络策略需要独立迁移项目，不能在维护版本中直接提高而不做 SAF/MediaStore 回归。
5. MPV 启动阶段立即初始化导致较高内存，建议在 0.6.9 设计“恢复状态轻量化 + 首次播放延迟加载”状态机。
6. 音源卡片的信息密度仍高；建议后续改为摘要卡片 + 详情页，而不是继续向首屏叠加诊断操作。
7. 全仓 ESLint 尚有历史技术债，`StateMapper` 仍是非标准 Hook 封装；应在独立重构中迁移到标准外部 store 订阅 API。

## 6. 发布口径

0.6.8 可以描述为“稳定性与安全加固版”，重点强调歌单数据安全、文件扫描性能、智能歌单缓存、界面背景一致性、外部插件安装确认和 Release 签名门禁。不得宣称已经完成插件沙箱、凭证加密、Android 最新权限迁移或彻底解决 MPV 启动内存。
