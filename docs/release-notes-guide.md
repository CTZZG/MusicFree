# 发版说明怎么写

`docs/release-notes-v<版本>.md` 就是 GitHub Release 的正文，应用内“检查更新”对话框也逐行显示它
（“下载”一节除外，最多 40 行，超出的直接截掉）。`changelog.md` 每版一条，内容和它一致。

读者是用这个 App 听歌的人，不是开发者。每写一条先问三件事：用户会注意到吗？需要用户做什么吗？
更新前想知道吗？三个都不是，就不写。

## 要写

- **新功能**：做什么、在哪里打开、默认开还是关。路径用 App 里的原名，例如“基本设置 → 播放 → 音量平衡”。
- **修复**：写用户遇到的现象，不写原因。写“换音质后，显示的播放进度偶尔比实际慢一点”，
  不写“播放内核在音频数据没读满时把整段请求都算成已排队”。
- **需要用户注意或动手的变化**：最低系统版本、设置换了位置、默认值变了、不要卸载。
  “需要 Android 14 及以上”每版都保留：Android 13 及以下还在用 v0.11.6 的人也会收到更新提示
  （检查更新不看系统版本），只有正文能告诉他们装不了。
- **和隐私有关的事实**：例如崩溃记录只存在手机上、不会上传。
- **安全修复**：只有打进安装包的代码才写，一句“修复了一个安全问题”，不写包名和公告编号。
- **已知问题**和绕过办法。
- **没在真机或车机上验证过、用户可能还会碰到的修复**：写成请用户反馈，例如“如果在车机上仍遇到列表不对，
  请在 基本设置 → 开发选项 → 复制播放诊断 后反馈”。不写“只有单元测试”“没有真机验证”。

## 不写，写到哪里

| 内容 | 写到 |
|---|---|
| 验证过程：测试项数、模拟器、Beta / CI 编号、“候选包” | PR 说明；要长期留档的写进 `docs/handoff/` |
| 原因和实现：播放内核、取源、DEX、R8、反射、并发等 | PR 说明、`docs/handoff/` |
| 依赖升级、安全审计和例外、CI 与发版流程的改动 | `docs/architecture.md` |
| 构建号、提交、签名、libmpv 校验值 | 附件 `android-build-info.txt`（发版流程自动生成）和构建日志 |
| 给自己留后路的话（“不代表……”“不等同于……”） | 不写 |
| 测试里量到的精确数字 | PR 说明；正文只写用户感受得到的数，例如安装包大小 |

## 写法

- 开头一句话概括这一版。
- 一条只说一件事，开头就是用户看到的变化。
- 用 App 里的原名，不用内部词：播放内核、取源、焦点、意图、候选、门禁。
- 小节只用：升级前请注意、新功能、改进、修复、改进与修复、已知问题、下载。没有内容的小节不写。
- 对话框里（不含“下载”）不超过 30 行，每行不超过 100 字；小版本控制在 10 行左右。

## 模板

```markdown
# MusicFree v<版本>

<一句话：这一版主要改了什么。>

## 升级前请注意

- 需要 Android 14 及以上。Android 13 及以下请继续使用 v0.11.6。
- 直接覆盖安装即可。不要先卸载，卸载会清空歌单、设置和插件。

## 新功能

- <功能名>：<做什么>。在 <基本设置 → … → …> 打开，默认<开/关>。

## 修复

- <用户遇到的现象>，现在已修正。

## 下载

大部分手机下载 **arm64-v8a** 版；不确定就下载 **universal** 版（体积大一些，所有手机都能装）。

- `…-app-arm64-v8a-release.apk`：大部分手机
- `…-app-armeabi-v7a-release.apk`：32 位系统的手机
- `…-app-universal-release.apk`：通用版
- `…-app-x86_64-release.apk`、`…-app-x86-release.apk`：模拟器用

各文件的 SHA256 校验值见 `SHA256SUMS.txt`。
```

## changelog.md

每版一条，放在最上面：第一行是 `` `年.月.日 v<版本>` ``，下面是编号条目 `1. 【分类】……`。
内容和发版说明一样，只写用户看得到的变化。分类用功能名（播放、车载、歌词、下载、隐私……），
不用【验证】【发布】【依赖】【维护】【内核】。

## 自动检查

`src/utils/__tests__/releaseNotesPolicy.test.ts`（`npm run verify` 里的 Jest 一步）检查 `package.json`
当前版本的发版说明和 `changelog.md` 最上面一条：小节标题、对话框行数和每行长度，以及明显的内部用语
（验证、模拟器、Beta、CI、PR、R8、依赖、审计、libmpv、提交哈希等）。行数按应用里对话框的实际显示
（`src/utils/releaseNotes.ts`）计算。

它只拦得住明显的问题，写得像不像人话还得自己读一遍，用户不需要的就删。确实需要新的小节标题，
或者被拦的词其实是 App 里的原名，就改检查里的清单，并在 PR 里写明原因。

## 发版后改说明

改 `docs/release-notes-v<版本>.md`（和 `changelog.md` 对应的一条），合入 `feat/mpv-only`，再手动运行
Android Release Build、勾选 `notes_only`、版本填当前版本：只更新 Release 正文，不重新构建、不动安装包。
同一分支上正在跑的构建会让它排队。只能这样更新 `package.json` 当前版本的说明，旧版本的说明不再改。
