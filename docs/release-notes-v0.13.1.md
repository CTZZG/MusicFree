# MusicFree v0.13.1

修正换音质后进度读数落后，Android Auto 列表请求和崩溃记录脱敏的问题。

## 升级前请注意

- **仍需 Android 14（API 34）及以上**。Android 13 及以下请继续使用 v0.11.6 或更早的适用版本。
- Android 14 及以上请覆盖安装。不要先卸载旧版，卸载会清除应用里的歌单、设置和插件。

## 修正

- **换音质后进度更准**：同一首歌切换音质后，播放进度读数偶尔会比实际位置落后一小段（模拟器上见过最多约 0.25 秒）。原因是播放内核在音频数据没读满时，把整段请求都算成了已排队。现在只算实际交给系统播放的部分。这是进度计时的修正，没有在真机上做听感验证。
- **Android Auto 列表不再串**：车机上反复打开“我喜欢”“最近播放”时，上一次超时后迟到的回复不会再填进新打开的列表。
- **崩溃记录遮得更全**：基本设置 → 开发选项 → 复制播放诊断 里的崩溃记录，现在也会遮掉多层转义的 JSON、被截断的记录、refresh_token / client_secret / x-api-key 这类凭据名、请求头的名称/值写法、整串 Cookie，以及 ws://、rtmp:// 等地址里的用户名密码。记录仍然只在手机上，不联网、不上传。

## 维护

- 播放内核 libmpv 四个架构全部按锁定的源码重新编译，只改了上面的计时，其余解码和运行库不变。
- 发版检查记录每个安装包里 libmpv 的校验值，防止把旧缓存当成新库发出去。
- Android 17 后台音频加固检查改为全程采集日志；采集中断时判失败，不再当成“没有被拦下”。

## 下载

大部分手机下载 **arm64-v8a** 版；不确定时下载 **universal** 版（体积较大，包含所有架构）。

- `…-app-arm64-v8a-release.apk`：大部分手机
- `…-app-armeabi-v7a-release.apk`：32 位系统的手机
- `…-app-universal-release.apk`：通用版
- `…-app-x86_64-release.apk`、`…-app-x86-release.apk`：模拟器

各文件的 SHA256 校验值见 `SHA256SUMS.txt`，构建来源和签名记录见 `android-build-info.txt` 及正式构建日志。
